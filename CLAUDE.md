# Brooke — проект

Будильник-мотиватор для iPhone. Владелец: Azamat (Windows, Git Bash, iPhone 14 на iOS 18.5, Mac нет). Общаться с ним по-русски, коротко и по шагам.

## Что где лежит

- `web/` — **основная версия, которой он пользуется**: один статический файл `web/index.html` (HTML + CSS + JS, без сборки и без зависимостей). Открывается в Safari на iPhone.
  - `web/test.html` — страница диагностики (версия iOS, память Safari, отметка сбоя).
  - `web/icon.png`, `web/icon-512.png` — иконки.
- `vercel.json` — публикация папки `web/` на Vercel без сборки.
- `deploy-vercel.sh` — публикация на Vercel одной командой (`bash deploy-vercel.sh`): git push → Node.js → Vercel CLI → вход → проект `brooke` → `vercel deploy --prod` → печатает адрес и копирует ссылку `…/?wake=1` в буфер.
- `.github/workflows/pages.yml` — старая публикация `web/` на GitHub Pages (запасной адрес).
- `Brooke/`, `project.yml`, `.github/workflows/build.yml` — нативное iOS-приложение на SwiftUI (AlarmKit для iOS 26+, фоновый режим для iOS 18). Собирается в GitHub Actions в неподписанный `Brooke.ipa`. Сейчас **не используется**: нет кабеля для Sideloadly. Не трогать без просьбы.

## Как работает веб-версия

- Звонит стандартный будильник iPhone («Часы»). Автоматизация в «Командах»: «Будильник остановлен → Открыть URL-адреса → `<адрес>/?wake=1`».
- Утро: фото слайд-шоу → «Я встаю» (включается его mp3) → пример средней сложности (двузначное × однозначное) → видео без пропуска → «Доброе утро» + серия дней → «Задачи на сегодня» (оценка Gemini) → «Начать день».
- Утро также запускается само, если Brooke открыт на телефоне (pointer: coarse) за 10 минут до / 90 минут после времени будильника и сегодня утро ещё не пройдено (`brooke.wokeDay`).
- Задачи: пишутся вечером на завтра (`planKey()` = день следующего будильника). За каждую выполненную — случайное видео-награда.
- ИИ: Gemini через ключ пользователя (`brooke.geminiKey`), модели по очереди: gemini-2.5-flash → gemini-flash-latest → gemini-2.0-flash. Ответ — JSON по схеме (сложность, причина, порядок, когда, мотивация).
- Синхронизация ноутбук ↔ телефон: секретный GitHub Gist (описание «Brooke · задачи (синхронизация)», файл `brooke.json`) по токену с правом `gist`. Синхронизируются только задачи, анализ ИИ и время будильника. Слияние по `updatedAt`, удаление — через `deleted: true`.

## Хранилище (важно)

- `localStorage` с префиксом `brooke.` — настройки, задачи, серия, ключи.
- IndexedDB `brooke` v2: `meta` (маленькие записи) + `blobs` (файлы). Файлы читаются **по одному**, только когда показываются: раньше загрузка всех видео сразу роняла Safari («Повторно возникла проблема»).
- Защита от сбоев: перед тяжёлыми действиями пишется `brooke.risky` (`boot` / `import` / `video`); если страница упала, следующий запуск — безопасный режим с кнопками удаления видео.
- У каждого адреса (GitHub Pages / Vercel) своя память Safari: при смене адреса фото, видео, трек и ключ Gemini нужно добавить заново, задачи вернутся через синхронизацию.

## Правила

- Не добавлять сборку, фреймворки и npm-зависимости в `web/` — это один файл, так проще и надёжнее на iOS 18 Safari.
- Никогда не коммитить токены и ключи (GitHub, Gemini, Vercel). `.vercel/` в `.gitignore`.
- Звук и видео со звуком в Safari запускать только внутри нажатия пользователя (поэтому есть кнопка «Я встаю»).
- Не загружать все медиа сразу; видео ≤ 250 МБ, трек ≤ 40 МБ.
- Перед публикацией проверить синтаксис JS: вырезать содержимое `<script>` из `web/index.html` и выполнить `node --check`.

## Публикация

- Vercel: `bash deploy-vercel.sh` (или `git push`, если Vercel подключён к GitHub).
- GitHub Pages: `git push` (workflow `pages.yml`).
